## What to include when publishing a project

1. A short problem statement and intended users.
2. A workflow diagram or clear node-by-node explanation.
3. A list of integrations and required credentials.
4. Example input and output with personal data removed.
5. Setup instructions and environment-variable names (never secret values).
6. Screenshots or a short demo, where available.
7. Known limitations, error handling, and testing notes.
8. An honest implementation status: Planned, In Progress, Tested, or Deployed.

For documentation conventions, see [projects/README.md](projects/README.md).
