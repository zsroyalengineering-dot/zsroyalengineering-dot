# Project Documentation

Each project folder contains a standalone overview of a workflow or automation build.

## Recommended documentation structure

- **Overview:** what the project does.
- **Problem:** the manual task or business challenge.
- **Workflow:** trigger, processing, decisions, and outputs.
- **Tech stack:** only tools actually used.
- **Setup:** prerequisites, credentials, and configuration.
- **Testing:** sample cases and expected results.
- **Error handling:** retries, validation, fallbacks, and alerts.
- **Security:** secret management and data minimization.
- **Status:** Planned, In Progress, Tested, or Deployed.

Before publishing a workflow export, remove credentials and personal data. Never upload API keys, OAuth tokens, private customer records, or unredacted execution logs.
